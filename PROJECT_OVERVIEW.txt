BACKEND (Node.js + Express)
- Express API with CORS + JSON parsing
- In-memory cache (NodeCache, 5-minute TTL)
- External providers:
  - Finnhub (quotes, profiles, news, peers, earnings, metrics)
  - NewsAPI (business headlines / WSJ)

Key backend endpoints (current)
- GET /api/stock/search?q={query}
- GET /api/stock/:symbol
- GET /api/stock/:symbol/related
- GET /api/stock/:symbol/earnings
- GET /api/market/overview
- GET /api/market/gainers
- GET /api/market/losers
- GET /api/crypto
- GET /api/news
- GET /api/news/wsj
- GET /api/news/:symbol
- GET /health

Rate-limit hardening work already added
- Reduced homepage market-mover API fanout to avoid Finnhub free-tier exhaustion
- Cached market movers snapshot reused for gainers/losers
- Cached fallbacks for stock detail when provider is temporarily throttled
- Crypto symbol fallback handling in stock detail route (e.g., BTC, ETH)

═══════════════════════════════════════════════════════════════════

DATA & STORAGE MODEL (CURRENT BEHAVIOR)

Authentication / user profile
- Firebase Auth (Email/Password)
- Firestore `users` documents for profile data

Watchlist
- Stored in Firestore `watchlists` collection (per user)
- Each entry now includes:
  - symbol
  - name
  - addedAt (timestamp)
  - addedPrice (entry/watch price)
  - logo
- Local fallback storage is used on web if Firestore write fails (to avoid silent UX failure)

Portfolio / paper trading
- Firestore `portfolios` doc per user (when available)
- Local fallback portfolio storage used if Firestore read/write fails
- Starting paper trading cash: $100,000
- Holdings track symbol, shares, avgPrice, purchaseDate

CURRENT KNOWN LIMITATIONS / NOTES
- "People who own X also own" is currently implemented via peer/comparable-stock data, not true holder-overlap ownership data.
- Full earnings call transcripts are not yet integrated (earnings report numbers are available).
- Search endpoint still makes many upstream requests and can be optimized further.
- Some data paths use local fallback storage when Firebase write/read is blocked by rules/config (helps web testing UX).
- Expo asset image files referenced in app.json should exist for production builds.

LOCAL RUN INSTRUCTIONS (WEB)
1. Start backend
   cd backend
   npm install
   npm run dev

2. Start frontend (Expo)
   cd frontend
   npm install
   npm start -- --web --port 8081

3. Open web app
   http://localhost:8081

Backend health check
- http://localhost:3000/health

Important configuration
- backend/.env (Finnhub + NewsAPI keys)
- frontend/src/utils/firebase.js (Firebase config)
